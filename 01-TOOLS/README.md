# 01-TOOLS

> Generated by `harness` on 2026-09-21.

Operational tooling for **IQP TMS iDempiere**. Each provider directory combines credential templates with the scripts that consume them. Runtime dependencies belong to the product code, not here.

## Conventions

- Tool directories use uppercase names with underscores.
- One directory represents one external provider.
- Real `.env` files and keys are local, permission-restricted, and never committed.
- Every automated tool starts with a parameter-free `test_connection` smoke test.
- Destructive scripts require an explicit confirmation flag and default to preview mode.

## Adding a new tool

1. Copy `01-TOOLS/_TEMPLATE` to `01-TOOLS/<NAME>`.
2. Define only the credential names actually required in `.env.example`.
3. Create a local `.env`, fill it from the provider dashboard, and set mode `600`.
4. Implement and run `test_connection.{sh,py}` before adding operational commands.
5. Document credential rotation and failure recovery.

## Philosophy

- No speculative providers.
- Smoke-test credentials before other operations.
- Keep credentials and their operator scripts together without exposing them to runtime code.
